# Routing

## 输出规则

若输出给人看，至少总结：

- 公司名与证券代码
- 公告标题
- 公告日期
- 原文链接
- 提取结果里的关键字段

若输出给脚本或 Agent，优先使用：

```bash
clawshire ... --format json
```

## 调用限制

- 日期范围不宜过大，避免无意义拉取过多结果
- 若用户未指定数量，默认按 CLI 默认分页返回
- 若用户明确要求全部数据，使用 `--page-all`，但要避免在超大范围上盲目调用

## 事件识别路由

以下意图优先走 `notice detect-events`：

- 用户明确说要识别“回购 / 减持 / 业绩预告 / 中标 / 处罚”等事件
- 用户要事件计数，而不是原始公告列表
- 后续步骤要继续按事件类型筛选、排序或汇总

以下情况仍优先原始查询命令：

- 用户只要公告列表或 PDF 链接
- 用户给的是公告原文链接
- 用户要查看某一条公告的原始标题和发布时间，但不需要事件归类
